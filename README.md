# AGIbar · H3 Studio

> 公共站点新版本见 [cloud/README.md](cloud/README.md)：Cloudflare 静态托管、MiniMax / Kimi 模型页签各自提供健康探测、Playground 与本地配置提示词，店内浏览器直连与访客 localStorage。以下内容仅描述保留的旧版 Node + curl 本地工作台。

本地运行的 MiniMax H3 视频测试工作台。浏览器配置请求，本地 Node 服务使用真正的 **curl** 调用同步接口，展示 MP4、HTTP 状态、错误响应与命令预览。没有第三方运行依赖，也不需要前端构建。

## 启动

需要 Node.js 22+ 和支持 `--fail-with-body` 的 curl（7.76+）。在店内 WiFi 环境运行：此 H3 endpoint 的网络访问条件由服务方控制，其他网络不保证可达。

```sh
cd /Users/atlas/Github/AGIbar
node --version
curl --version
node server.mjs
```

打开 <http://127.0.0.1:4317>。如端口已占用，可以使用 `PORT=4318 node server.mjs`。无需安装 npm/pnpm 包；也可用 `pnpm start`。

1. 输入自己的 API key，确认完整 H3 endpoint。
2. 修改提示词、尺寸、帧率及高级参数，检查右侧 curl 命令。
3. 点击「生成视频」。真实请求可能产生服务端费用，界面不会自动发送生成请求。
4. 成功后播放或下载 `h3-video.mp4`；失败时查看「响应详情」中的 HTTP 状态、curl 退出码、stderr、响应头与响应体。
5. 「H3 队列与历史」按创建时间从新到旧列出生成中、完成、失败或取消的任务。刷新网页会从本地服务恢复正在运行的 H3 任务并继续轮询；完成后可选择历史任务重新预览、下载或查看响应。运行期间先等待或取消当前任务，再查看其他历史结果；刷新不会重新发送生成请求。

队列每 5 秒自动同步，仅属于当前本地服务进程。沿用现有保留窗口：任务创建满 1 小时且已结束后，在下一次每分钟清理时删除；运行中的任务不会被清理。服务重启后历史与临时视频无法恢复，即使磁盘残留也不能从页面找回，请及时下载。此恢复行为仅适用于 H3，不适用于下方 K3 监测。

默认协议来自提供的 curl 示例：

- `POST https://token.agi.bar/minimax-h3/head/v1/videos/sync`
- `Authorization: Bearer <API key>`
- multipart 字段：`prompt`、`width`、`height`、`aspect_ratio`、`fps`、`num_inference_steps`、`flow_shift`、`seed`、`extra_params`
- `extra_params` 默认 `{"task":"t2va","duration":5,"audio_flow_shift":3}`
- 必须使用完整的视频 endpoint，`https://token.agi.bar/v1` 是通用 Base URL，不能直接替代它。

`--form-string` 将所有参数作为普通文本发送，避免提示词中的 `@` 被 curl 解释为本地文件。高级 JSON 原样发送，时长输入会更新其中的 `duration`。本地数值限制只用于阻止明显错误的输入；不代表服务端支持全部组合，API 仍可能返回校验错误。

## 密钥与本地数据

- API key 默认预填店内静态 Key，并在此浏览器的 `localStorage` 保存，便于下次打开继续使用。可用输入框旁的「清除」删除已保存值；它不会写入服务端、项目文件或终端日志。请不要在共用浏览器中保存自己的其他密钥。
- 网页命令只使用 `$H3_API_KEY` 占位。复制到终端执行前，自行设置环境变量；不要把真实 key 贴进共享截图或 Git。
- 实际调用通过 `spawn('curl', args)` 执行，不使用 shell。Authorization 经 stdin 传给 `curl --header @-`，不放入 curl 进程参数；不加载用户 `.curlrc`，不跟随重定向。H3 请求强制 `--http1.1`，避开该店内链路已观察到的 HTTP/2 framing 错误。
- 服务仅监听 `127.0.0.1`，验证 Host 和 Origin，仅接受 JSON 请求，不允许跨域调用。不应直接暴露在公网。
- 默认 endpoint 使用 HTTPS。可编辑到其他 HTTPS endpoint；仅本机 mock 允许 HTTP。请确认 endpoint 可信，因为密钥会发送到该地址。
- curl 的原始响应只进入进程内存；响应头与响应体中的完整 API key 字节串在写入临时文件前替换为 `[REDACTED]`，文件权限为 `0600`。若视频内容中出现完整 key，脱敏后会阻止该视频下载，避免交付损坏的 MP4。
- 视频与脱敏响应暂存在系统临时目录 `agibar-h3-*` 下，路径由程序生成，不接受用户文件路径。已结束任务自创建满一小时后清理，正常关闭服务也会删除。强制终止进程或系统崩溃可能留下临时目录，包含生成内容及脱敏响应。
- 展示与持久化均遮盖输入的完整 API key；服务端若以其他编码或分散片段回显敏感内容，无法保证自动识别，因此不要公开分享诊断内容。

## Kimi K3.1 Pro 可用性监测

右侧监测面板默认使用通用 Base `https://token.agi.bar/v1`，复用左侧 API key，包括已保存在此浏览器 localStorage 的值。若使用其他 Base，请确认地址可信，密钥会发送到该地址。

点击「开始监测并允许通知」后立即探测，以后每次探测完成后等待 5 分钟再试，不会重叠。请求为 `POST <Base>/chat/completions`，模型固定 `k3.1-pro`，消息为 `Hi`，`max_tokens: 1`，`stream: false`。探测可能消耗额度；HTTP 429 表示额度或速率受限，不能仅凭该状态判断具体恢复时间。

收到 HTTP 2xx 且含 chat completion 的 `choices[].message` 后，页面显示可用，并尝试发出一次系统通知，随后自动停止。初次探测已可用也会通知并停止。其他 HTTP 状态、错误 JSON、无效响应、连接失败或超时都会等待下次探测。每次连接最多 10 秒，总等待最多 45 秒，响应最多约 64 KiB；不跟随重定向。探测走本地服务和 curl，凭证经 stdin 传入；响应只在内存解析，页面仅接收状态摘要，不落盘，也不展示上游错误体。

通知需要浏览器支持 Notification API 并允许当前站点权限；通常在 localhost/127.0.0.1 可用。权限请求与探测同时开始，权限弹窗一直等待也不会阻塞探测。若恢复时权限仍在等待，页面先显示可用并停止探测；随后允许权限会补发一次通知。手动停止或新一轮监测会取消上一轮待发通知。若拒绝权限或浏览器不支持，页面仍会显示可用状态；可在浏览器站点设置中重新允许。系统勿扰、浏览器或操作系统设置可能屏蔽通知。

需要保持页面和本地服务开启；关闭、刷新页面或点击「停止监测」会取消本次请求并停止后续探测，不会自动恢复。更改或清除 API key 也会停止。后台标签页休眠可能延迟探测，本功能不承诺严格每 5 分钟或后台常驻运行。停止本地请求不保证上游立即终止计算或计费。

## 行为限制

同步生成最多等待 20 分钟，连接超时 30 秒，最大响应 150 MiB；一次只运行一个生成请求，可主动取消 curl。取消本地连接不保证服务端停止计费或生成。

成功条件是 HTTP 2xx、curl 正常退出，且响应具有 MP4 `ftyp` 标识。JSON 错误不会被当作视频下载。错误响应体显示前 64 KB，stderr 显示末尾 20 KB。视频只在当前服务进程中可用，重启后链接失效。

```sh
node --test test/*.test.mjs
```

测试通过本机模拟接口验证 multipart 字段、真实 curl、MP4 下载、错误响应保留、参数拒绝、响应头/体在落盘前的密钥遮盖（含跨传输块与视频回显）、并发限制与取消。K3 测试覆盖最小请求、429→可用、无效/超大响应、禁止重定向、断连取消、五分钟调度、一次通知和停止后忽略迟到结果。不会调用真实 H3/K3，也不会消费额度。真实服务仍需手动验收；系统通知交付取决于浏览器权限与操作系统。
